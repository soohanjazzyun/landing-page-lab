# Earn 3,000 genuine stars by making the work useful

Owner: Jazz. Planning date: 2026-11-03. Execution update: 2026-11-04. Public project: [Landing Page Lab](https://github.com/soohanjazzyun/landing-page-lab). Audience: English-speaking solo founders and developers who have a product README, a coding agent, and an unclear landing page.

**Goal:** 3,000 genuine GitHub stars. This is an objective, not a forecast, a 14-day promise, or a result already achieved. Stars, installs, observed real use, and useful contributions are different signals. No paid traffic, artificial engagement, or vote coordination is assumed.

## The product and the reason to share it

**Current published opening:** I gave my coding agent a marketing department.

The initial 27-second, revised 34-second, and portrait-led 14-second X posts are public. The latest [recorded case](portrait-case.md) uses actual agent recommendations on a fictional brief. Its source, task, raw output and limitations are inspectable. This publication does not establish growth or a winning hook.

Story makes the product understandable. Resonance chooses the people the page is for. Offer makes the actual deliverables, effort, terms, and commitment easier to evaluate. These are original operational skills by Jazz, with inspiration credited to Donald Miller, Seth Godin, and Alex Hormozi. They are not author impersonations, book substitutes, or endorsed implementations.

The first public format is **One Product, Three Pitches**: the same source facts and visual design, with three different message decisions. Publish the source, copy, reasoning, unsupported claims, and manual edits so readers can inspect the work. The opening examples are fictional and authored. A browser prompt composer prepares a task locally; the user's coding agent performs the actual work.

**First useful result:** a founder can see one consequential decision about explanation, audience, or commitment, then use that decision on an existing page. A whole-page rebuild is optional. The narrow first task is one hero audit.

## One repeatable loop

```text
Public-safe product brief
  → three inspectable pitches
  → owner corrects the facts and decides what fits
  → exact case gets publication consent
  → useful artifact about the founder's own product
  → voluntary sharing, real trials, and reproducible failure reports
  → a focused improvement and the next case
```

The participant receives the drafts and reasoning regardless of whether they share or star. Only show a founder's name, assets, or words with permission for that exact use. Keep failed assumptions and criticism in the record. A useful public case is the main asset; a generic “please star” announcement is not the growth engine.

## Review points toward 3,000

| Observed star level | Work to earn the next review | Evidence beyond stars | Decision |
| --- | --- | --- | --- |
| Before a baseline | Working public install of all three skills; inspectable examples; actual release verification | A clean install and an external person completing a permitted narrow task, when a volunteer is available | Repair a broken first task before broader promotion |
| First 100 | Answer launch questions; observe willing users; publish one consented case when available | Source/output records, recurring confusion, blocked steps | Tighten the brief and quick start around the actual failure |
| 100-500 | Repeat the strongest case format; make one substantive improvement | Completed tasks and independent shares from relevant builders | Repeat useful work, not simply more posts |
| 500-1,500 | One agreed complementary creator build; a small reproducible case gallery | At least two contexts bringing real trials; sustainable maintainer time | Focus on the audience where the workflow is useful |
| 1,500-3,000 | A substantial release from recurring failures; reintroduce it through actual cases | Repeat use, voluntary recommendations, useful contributions | Expand the loop that works; keep failure evidence visible |

These are review points, not fixed schedules. We do not know the exposure, conversion rate, or time required to reach them. Other repositories' cumulative stars demonstrate possible interest in agent skills; they do not predict this project's outcome. ## Experiments and decision rules

The [hypothesis sheet](../launch/hypotheses.csv) labels every planned test `unmeasured`. A future controlled creative comparison should keep the clip and destination constant. The actual published posts changed both opening and video, so they do not isolate either effect. Organic sequential posts have different audiences and timing, so their results cannot establish causal lift. Do not declare a winner from a handful of impressions or comments.

| Actual signal | Next useful action |
| --- | --- |
| Few qualified visitors | Change the example or distribution context; silence alone does not prove the skill is wrong |
| Visitors do not reach installation | Observe the route and remove the first clear obstacle |
| Installs without usable output | Watch one permitted run; inspect the first wrong fact or decision |
| Useful output without voluntary sharing | Offer a concise share artifact about the founder's product, with no requirement to post |
| Repeated useful runs in one niche | Make the next case for that niche and approach one adjacent creator |
| Heavy support or recurring wrong assumptions | Narrow the task and fix the skill before seeking more reach |
| Impressions but no task evidence | Treat it as reach, not product validation |

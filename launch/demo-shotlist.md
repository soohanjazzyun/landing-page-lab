## Recording checklist

- Lock viewport, zoom, layout, colors, type, images, animation speed, and product facts across variants. Show any changed section order as a disclosed messaging decision.
- Give each pitch enough time to read. Use captions, a quiet background, and visible cursor actions. Do not cover the example label with subtitles.
- Record 16:9 at 1920 × 1080; make a separate 4:5 crop only if the full message remains legible. A legible still is better than a tiny full-page video.
- Record against a release commit. Save commit/tag, capture date, source brief, exact prompt, skill, agent/model if used, output, and manual edits with the case.
- If the showcased copy is authored, say so. If a live agent run is sped up, disclose speed-up and elapsed time. Do not edit out a correction and then call the run untouched.
- Review the actual audio, captions, flicker, crop, live links, and mobile playback before attaching it to a post.

## Two supporting cuts

**8-second hook:** before hero for 2 seconds, three labeled pitches for 4 seconds, repository card for 2 seconds. Caption: `One product. Three pitches. Same facts and design.`

**90-second technical cut:** source and constraints, exact invocation, complete output, evidence gaps, manual edits, and one unresolved tradeoff. This is the useful companion for a technical audience; it does not need fast motion or a sales voice.

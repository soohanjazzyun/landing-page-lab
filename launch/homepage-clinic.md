# Founder Clinic: one product, three pitches

## Public invitation

**Your repo has the facts. Let's find the pitch.**

Bring a public README or page, one intended buyer, and one real next action. Jazz will select a few products for a public Landing Page Lab walkthrough: Story, Resonance, and Offer, with the same product facts and visual design.

You get the three working drafts, the reasoning, the evidence gaps, and a build prompt you can use yourself. Selection depends on learning value and available time. A submission is not a guaranteed review or a promise of better conversion. No star, repost, subscription, or positive review is required.

Submit with the [Founder Clinic issue form](https://github.com/soohanjazzyun/landing-page-lab/issues/new?template=homepage-clinic.yml) after the repository is public. Public issues are public immediately. Share only material you own or have permission to share. Use the skill privately if your input cannot be public.

## Intake and selection

Ask for the public source URL and current copy; intended customer and task; actual CTA; shipped features and public terms; allowed evidence; constraints; preferred credit; and whether the owner wants a separate publication review. Reject secrets, personal customer data, unverifiable performance claims, and material submitted by someone without authority.

Prioritize a product with a concrete buyer task, a short source brief, an owner who can check facts, and a useful disagreement among the three pitches. Work on at most two cases at a time. Do not select by star count or willingness to praise the skill. If the queue exceeds capacity, mark requests pending without promising dates.

## A 45-minute working session

| Time | Jazz does | Artifact / decision |
| --- | --- | --- |
| 0-5 min | Confirm owner, allowed public facts, buyer, CTA, and exclusions | Source ledger; no hidden research assumptions |
| 5-10 min | Ask the founder to explain what a visitor must understand | One task and one action to preserve |
| 10-25 min | Run the three skills against the same brief in the same agent/model where available | Raw outputs with prompt, version, and run metadata |
| 25-35 min | Ask the founder to flag wrong assumptions and pick useful decisions | Corrections, founder decisions, and unresolved tradeoffs |
| 35-40 min | Put each pitch in the same visual shell; disclose manual edits | Three comparable screenshots plus source text |
| 40-45 min | Ask whether the result is usable and what still blocks it | Observed task outcome, optional feedback, next revision |

This timing is an operating budget, not a claim about typical completion time. Record actual time. A founder saying a draft is useful is qualitative feedback, not proof of sales impact.

## Publish only the agreed case

1. Prepare the exact draft, screenshot/video, credit, links, and any quote.
2. Obtain [specific owner consent](owner-consent.md). Initial issue intake does not authorize a promotional case, testimonial, or unrelated personal information.
3. Publish source facts, three pitches, decisions, metadata, edits, limitations, and the final owner-approved credit. Mark unpublished founder decisions as proposals.
4. Offer the owner a small share card about their product. Sharing remains optional; do not script praise or ask for votes.
5. Link an issue to each actual skill failure. Change the skill only when the correction generalizes beyond this one product.
6. Record one completed case in metrics only after a real founder finishes the workflow and its outcome is recorded. Authored fixtures are not user cases.

Use [One Product, Three Pitches](one-product-three-pitches.md) as the case format. Respect corrections and removal requests for the project's own gallery where practical. Explain that public Git history and independent reposts may remain accessible.

## Five recurring episode angles

| Angle | Hook | Inspect |
| --- | --- | --- |
| Category | `The code works. Can a stranger tell what it does?` | A concrete task replaces an abstract category |
| Audience | `One README can hide three different customers.` | The chosen audience and who should choose another tool |
| Commitment | `A clear headline still needs a clear next step.` | What the buyer gets, does, and needs to know |
| Evidence | `A new product can explain itself without fake social proof.` | A source-backed demo replaces an unsupported claim |
| Tradeoffs | `The strongest pitch may leave someone out.` | Useful exclusions without pretending features disappeared |
